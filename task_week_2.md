На другий тиждень ми переходимо від "тіла" (інструментів) до **"мозку"** (ШІ). Твоя мета — навчити Gemini не просто балакати, а генерувати об'єкти `Task`, які твій `Executor` з першого тижня зможе зрозуміти та виконати.

Ось детальний план, як "подружити" PydanticAI та твій реєстр інструментів.

### **Тиждень 2: The Brain (Gemini + PydanticAI Integration)**

**Мета:** Створити агента-планувальника (Planner), який перетворює людську мову на структурований JSON-об'єкт та передає його системі виконання.

#### **1. Налаштування інтелектуального ядра**

* **Файл:** `config.py`
* Зареєструй API-ключ Gemini.
* Визнач базові параметри моделі (наприклад, `gemini-1.5-flash` для швидкості або `pro` для складних завдань).


* **Файл:** `infrastructure/llm_client.py`
* Ініціалізуй клієнт Gemini через `google-generativeai`.



#### **2. Створення системного промпту (The Soul of the Agent)**

Це найважливіша частина. Ти маєш пояснити агенту, хто він і як користуватися твоїми інструментами.

* **Задача:** Написати інструкцію, де вказано:
* "Ти — Akashi, системний оркестратор".
* "Твій вихідний формат — ТІЛЬКИ об'єкт Task".
* "Ось список дозволених дій з твого вайтліста".



#### **3. Реалізація PlannerAgent (через PydanticAI)**

Замість того, щоб парсити текст вручну, ми використовуємо `result_type` у PydanticAI.

* **Файл:** `core/planner.py`

```python
from pydantic_ai import Agent
from core.schemas import Task

# Ми кажемо агенту, що він МАЄ повернути об'єкт класу Task
planner_agent = Agent(
    'google-gla:gemini-1.5-flash',
    result_type=Task,
    system_prompt=(
        "You are Akashi, a system orchestrator. "
        "Based on user request, choose the correct action and params. "
        "Use only actions allowed in the registry."
    ),
)

```

#### **4. Ланцюжок "Запит — План — Виконання"**

Тепер треба з'єднати все разом у `main.py`.

* **Кроки розробки:**
1. Отримати `user_input` (наприклад: "Відкрий мені діскорд").
2. Викликати `planner_agent.run(user_input)`.
3. Отримати структуровану таску `result.data`.
4. Передати цю таску в `Executor.execute(task)`.



#### **5. Обробка "незрозумілих" запитів**

Що робити, якщо користувач просто каже "Привіт"?

* Тобі потрібно навчити агента розрізняти **балачки** та **команди**.
* **Рішення:** Можна додати в `Task` поле `action: Literal["chat", "open_app", ...]`. Якщо це "chat", система просто виводить текст.

---

### **Чек-лист результатів 2-го тижня:**

1. **Зв'язок з API:** Ти успішно відправляєш запит до Google Gemini.
2. **Structured Output:** Модель не пише "Я зараз відкрию...", а мовчки повертає валідний об'єкт `Task`.
3. **Автоматизація:** Після введення фрази в консоль, програма (наприклад, Калькулятор) реально відкривається без твого втручання в код.
4. **Валідація:** Якщо ШІ намагається викликати команду, якої немає у вашому `whitelist.json`, Pydantic викидає помилку (Validation Error).

### **Порада для диплома (Pro-tip):**

На цьому етапі ти можеш реалізувати **"Dry Run"** режим. Це коли агент показує: *"Я збираюся виконати команду X з параметрами Y. Дозволити?"*. Це початок твого **Human-in-the-loop**, про який ми говорили раніше. Для захисту диплома це виглядає дуже професійно.

**З чого почнеш розробку на цьому тижні?** Можемо підготувати `system_prompt`, який ідеально опише твій динамічний вайтліст для моделі.
