# Session 2026-03-10

## Проблеми що виникли під час тестів

1. **`cd` не працює** — LLM повертав `params: {"path": "..."}`, але handler очікував `args: list[str]` → команда ігнорувалась
2. **`cd` не зберігається між командами** — кожен `subprocess.run` — новий shell, зміна директорії не впливає на наступні кроки
3. **Один Task на запит** — агент повертав лише один `Task`, не міг розкласти складний запит на кілька кроків
4. **Немає перевірки результату** — тільки stdout, без stderr/returncode; LLM не міг реагувати на помилки виконання
5. **LLM не знає ОС** — міг генерувати команди несумісні з поточною платформою

### Ключова логіка

**`cd` перехоплення** (без subprocess):
```python
if name == "cd":
    new_cwd = os.path.expanduser(path)
    if not os.path.isabs(new_cwd):
        new_cwd = os.path.normpath(os.path.join(session.cwd, new_cwd))
    if os.path.isdir(new_cwd):
        session.cwd = new_cwd  # зберігається між командами
```

**Корекційний цикл в `main.py`**:
1. Виконати план → зупинитись на першій помилці
2. Зібрати результати → сформувати correction prompt
3. LLM генерує новий Plan → HITL → виконати

**Planner system prompt тепер включає**:
- `platform.system() + platform.release()` → LLM знає ОС
- Інструкція передавати аргументи як `{"args": ["arg1"]}` (не `{"path": "..."}`)
- Інструкція додавати верифікаційні кроки: після `cd` → `pwd`, після `mkdir` → `ls`
